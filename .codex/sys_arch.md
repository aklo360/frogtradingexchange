## App Layout

- `apps/ui`: Next.js 15 App Router frontend for Frog Trading Exchange.
- `apps/ui/src/app/profile`: wallet-connected Frog identity workspace backed by Tapestry profile/social/activity data and Solana NFT ownership. It renders honest disconnected/loading/error/no-profile states, real Frog/follower/following/recent-trade metrics, an owned-Frog collection and profile-picture picker, recent activity, and threshold-based milestones; no synthetic XP or rank is presented as account data.
- `apps/ui/src/app/ribbot`: FTX-owned Ribbot browser control workspace. It exchanges Telegram `/control` codes for short-lived account sessions and presents FTX-stored account, simple/advanced mode, buy/sell presets, separate priority fees, confirmation/sell protection, token-rule automation opt-ins, the separate Instant Auto Buy amount/liquidity/market-cap profile, lists, and wallet state in a flat scan-first desktop grid that linearizes at mobile widths. It mounts a scoped Privy React provider only when a public app ID is configured. Telegram-only login never creates another wallet; export and signer controls require an exact Privy-user/Telegram-user/Solana-wallet match. Privy's isolated modal handles key export, `removeSigners` removes app signers after explicit confirmation, and `addSigners` restores only the configured signer/policies before FTX clears its local bot-access pause. No key material enters FTX or Ribbot. UI tests cover session exchange and FTX-owned preference saves; local browser checks cover empty and mocked populated states at 1440px/390px without horizontal overflow.
- `apps/ui/src/app/perps`: Read-only Imperial perps terminal prototype. It consumes public Imperial endpoints for market data, status, stats, and route previews; it renders TradingView Lightweight Charts candlesticks from Coinbase 15-minute candles for supported markets and links to GMGN kline charts for mapped Solana token assets. Live order placement is intentionally disabled until Imperial auth, deposit signing, order-bot health, and rejected-order handling are validated end to end.
- `apps/api`: Cloudflare Worker API for Titan quote/swap integration.
- `apps/api/src/airdrop.ts`: DAEMON airdrop API and `AirdropCoordinator` Durable Object. It stores claim challenges, queued claims, used Frog mint IDs, finalization state, payout transaction hashes/status, and wallet event rows.
- `apps/api/src/tradingBot.ts`: Ribbot-facing trading-bot API and `TradingBotAccountStore` Durable Object. It exposes non-secret config, owns wallet provisioning, and stores non-secret account snapshots/preferences/referrals/control codes/control sessions/control wallet actions/staged automation orders/copytrade configs/sniper configs/auto-buy rules/multi-token baskets/auto-sell rules/execution events. Accounts persist up to ten wallet slots plus an active wallet ID while projecting the active slot into legacy single-wallet fields; Privy inventory sync accepts only embedded Privy Solana wallets, not linked external wallets. Account settings are authoritative for simple/advanced mode, confirmation, buy/sell presets, separate priority fees, sell protection, automation opt-ins, and the separate default-off Instant Auto Buy profile. Tagged instant executions must exactly match the stored amount/buy fee/slippage, be SOL-to-token, and pass a fresh FTX token/quote/liquidity/price-impact/market-cap review before the normal Privy boundary. The Worker reads SOL/SPL positions through Solana RPC, lazily indexes bounded confirmed swap fills from wallet-owned pre/post balances as deterministic account events, and builds net-flow PNL/activity with execution-metadata fallback plus live positions/Jupiter data. It also returns review-only token-cleanup candidates, token-safety mint risk reports, and market-risk pre-trade scans, gates live market execution through Privy Solana `signAndSendTransaction`, blocks live execution after FTX bot-access revocation, builds/gates live SOL/SPL withdrawal transfers through the same Privy path, and owns the scheduled and advanced automation registries/runners. The advanced runner observes copytrade signatures, Jupiter Tokens V2 recent first-pool launches, auto-buy state, and auto-sell triggers; every live path requires its own false-by-default feature gate plus the base FTX, account, RPC/risk, wallet, signer, and revocation checks. Current basket execution remains user-triggered. Referrals are tracking-only with no fee share or payout state.
- Scheduled-order safety is FTX-owned: the global `TradingBotAccountStore` atomically claims triggered orders before `/execute`, records `executing`/`executed`/`failed` state and DCA slice progress, rejects competing claims, and persists non-secret execution metadata. Every Privy transaction request carries a signed idempotency key. Ambiguous sends remain `executing`; after `TRADING_BOT_SCHEDULER_RECONCILE_AFTER_SECONDS`, FTX performs a read-only Privy lookup by execution reference, validates wallet/chain, and resolves confirmed/finalized or terminal failure states without resending. Expected status/execution-ID checks reject stale writes; pending/not-found/lookup errors remain visible. Ribbot only renders the returned state.
- Direct swap and withdrawal safety is also FTX-owned. Ambiguous Privy responses return `pending_reconciliation` with a deterministic reference; authenticated `/api/frogx/trading-bot/execute/status` and `/api/frogx/trading-bot/withdrawals/status` requests perform read-only Privy GET lookups, validate the stored wallet and Solana chain, resolve terminal state without resending, and record deduplicated terminal events. Ribbot locks unresolved tickets in non-secret cache and exposes Check Status callbacks.
- Bundle sequence safety is FTX-owned. `TradingBotAccountStore` atomically transitions a staged basket to `executing`, persists attempted/confirmed item counts, and rejects competing execution/cancellation. `/api/frogx/trading-bot/bundle-buy/status` checks only attempted deterministic Privy references and never calls wallet RPC; unresolved items stay locked, all confirmed items resolve `executed`, and confirmed partial completion resolves `failed` without auto-resuming unattempted items. Ribbot rehydrates this lifecycle from FTX and exposes Check Status instead of Execute for unresolved baskets.
- Advanced-monitor send safety is FTX-owned. Copytrade, sniper, auto-buy, and auto-sell persist a deterministic execution ID/reference in an atomic `staged -> executing` claim before calling `/execute`. Cron reconciliation and authenticated per-config status requests perform Privy GET only after `TRADING_BOT_ADVANCED_RECONCILE_AFTER_SECONDS`, validate wallet/chain, reject stale execution-ID writes, emit deterministic swap/activity events, and never resend. Confirmed one-shot auto configs become `executed`, provider-terminal auto configs become `failed`, standing copytrade returns to `staged` only after terminal resolution, and sniper returns to `staged` until its max-snipes cap is reached. Ribbot exposes Check Status only for executing configs and rehydrates the authoritative response.
- Managed copytrade strategy state is stored in `automation_configs.strategy_json`. FTX owns tags, fixed/percentage sizing and caps, separate sell fees, copy-sell/duplicate-buy controls, target minimums, renounced-mint checks, liquidity/market-cap filters, and token blacklists. `/api/frogx/trading-bot/copytrade/control` permits only `staged -> paused` and `paused -> staged`; executing configs cannot be paused, and paused configs are excluded from the active monitor scan. Legacy rows default to their prior 100%-up-to-cap and duplicate-buy behavior.
- Copytrade `excludePumpFunTokens` is false by default and is enforced from the parsed target transaction's account keys. FTX blocks only the official Pump bonding-curve program (`6EF8...F6P`) and deliberately does not classify the PumpSwap AMM program as bonding-curve activity, matching Trojan's pre-graduation filter semantics without trusting token names or metadata.
- `/api/frogx/trading-bot/copytrade/update` accepts a complete revalidated strategy only while its Durable Object row is staged or paused; the managed wallet is immutable, same-target edits preserve the monitor cursor, and target changes clear it for a fresh no-trade baseline. `/copytrade/duplicate` reads the source row inside FTX and creates a new staged row through the normal storage validator with empty monitor state. Ribbot cannot synthesize either mutation locally.
- Unresolved-execution escalation is shared across direct, scheduled, bundle, and advanced paths. `TRADING_BOT_MANUAL_REVIEW_AFTER_SECONDS` defaults to 900; FTX persists a deadline, records one deterministic non-secret `execution_manual_review_required` event, and upserts a case in the global Durable Object. A separate `TRADING_BOT_OPERATOR_TOKEN` protects pull-based list/acknowledge/reconcile routes. Acknowledgement is audit-only; reconciliation reuses wallet/chain-validated Privy GET paths and closes cases only on terminal provider or bundle evidence. Normal terminal reconciliation also closes queued cases. No route can force success/failure or resend.
- Sniper launch state is FTX-owned. The first enabled poll records the newest Jupiter first-pool cursor and never trades existing results. Later polls advance the cursor, deduplicate up to 100 processed mints, map `any|pump|raydium|moonshot` filters against Jupiter launchpad classification, and consume dry-run observations so a later live-gate change cannot retroactively trade them. Live buys require `TRADING_BOT_SNIPER_LIVE_EXECUTION_ENABLED=true`, the advanced/base monitor gates, account `sniperEnabled=true`, max-snipes/cooldown/spend limits, authority/liquidity/market-cap checks, SOL balance, FTX market-risk/Titan quote readiness, and normal Privy wallet/signer/revocation checks.
- `packages/shared`: placeholder shared workspace package.
- `scripts/dev-worker.mjs`: local Wrangler dev harness used by `pnpm dev`.

## Runtime Notes

- Local dev uses `pnpm dev` from the repo root.
- UI dev rewrites `/api/*` and `/rpc` to the local Worker.
- `scripts/dev-worker.mjs` loads root `.env*` files and writes forwarded Worker env into ignored `apps/api/.dev.vars` with owner-only permissions before starting Wrangler. Do not reintroduce secret-bearing `--var` command-line args.
- The airdrop route `/airdrop` is live for claim/reservation intake: `AIRDROP_ENABLED=true` in `wrangler.toml`. It uses the same home shell but disables background music on that route. Claim submission immediately reserves FCFS tiers from claim-time frog count: 1-9 frogs receive `0.10` `$DAEMON`, 10+ frogs receive `1.00` `$DAEMON`, until the 10 `$DAEMON` pool is exhausted. The UI must describe this as reserved, not airdropped, until a payout transaction hash exists. Enabling sends additionally requires `AIRDROP_PAYOUT_ENABLED=true`, optional `AIRDROP_AUTO_PAYOUT_ENABLED=true`, Worker secrets `AIRDROP_ETH_RPC_URL` and `AIRDROP_ESCROW_PRIVATE_KEY`, live Ethereum token bytecode, escrow `$DAEMON` balance, and escrow ETH gas.
- The perps route `/perps` is read-only. It should not submit Imperial orders until the JWT delegation flow, USDC profile deposit/withdraw transaction signing, `/status.orderBot` health gating, and `success:false` trading-response handling are implemented and tested.
- Ribbot must route trading and wallet operations through FTX/FrogX. Privy app secrets, authorization private keys, and wallet policy IDs belong in FTX Worker secrets, not in Ribbot. `RIBBOT_TRADING_BOT_TOKEN` protects Ribbot-only wallet, account/activity, referrals, control-code, swap, execute, positions, PNL, cleanup/safety/market-risk review, order storage/cancel, withdrawal/advanced-config storage/cancel/execute/status, and preference-validation surfaces; Ribbot sends the matching token as `RIBBOT_FTX_API_TOKEN`. Market and withdrawal execution require `TRADING_BOT_LIVE_EXECUTION_ENABLED=true`, a stored Privy wallet match, no FTX bot-access revocation, Privy app credentials, and Privy authorization signer credentials before FTX calls Privy Solana `signAndSendTransaction`; withdrawals also require Solana RPC. Activity/PNL/cleanup/safety/market-risk are review/read surfaces; PNL may append deterministic non-secret fill-index events after read-only Solana transaction inspection but cannot sign, broadcast, or resend. Limit/stop/trailing/DCA orders and copytrade/sniper/auto-buy/bundle-buy/auto-sell configs live in the FTX automation registry. Scheduler and advanced-monitor paths are dry-run by default; each live feature has a separate false-by-default gate and reuses the normal FTX risk and Privy controls. Sniper monitoring additionally requires `JUPITER_API_KEY` and its live path requires account `sniperEnabled=true`; `/sniper/status` is read-only. Bundle-buy is user-triggered and interrupted bundles never auto-resume. Control sessions expose stored non-secret account state only. Privy account controls and every live trading path need approved private verification. Referral payouts and realized/FIFO PNL remain unimplemented.
- DAEMON payout metadata is first-class Worker config: token `0x43298327b0249caF5A4942C6951F5Ac6AD7297A0`, escrow `0xC853Fc4dE86fC8868Fa89FC3B207d4592Db19e46`, 18 decimals. Admin export includes human `$DAEMON` amounts and ERC20 base-unit amounts.
- Airdrop frog counts use Solana DAS `searchAssets`, so local/prod eligibility requires a DAS-capable RPC such as Helius. Without it the UI must keep the payout/claim steps disabled.
- Production deployment is `pnpm run deploy:prod`, which deploys the API Worker and Cloudflare Pages UI. Confirm target/environment before any deploy.
- Secrets live outside git in env files and Cloudflare secrets; do not read, print, or rotate them unless AKLO explicitly asks.
